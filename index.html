LAYER Select Shop

Backend Project Case Study

01

Project Overview

LAYER Select Shop은 온라인 쇼핑몰의 주요 사용자 흐름과 관리자 기능을 직접 구현해보기 위해 제작한 개인 웹 프로젝트입니다.

사용자가 회원가입을 하고 로그인한 뒤 상품을 조회하고 검색하며, 원하는 상품을 장바구니에 담아 주문할 수 있도록 구성했습니다.

또한 관리자 영역을 별도로 구성하여 상품 등록·수정·삭제, 회원 관리, 주문 조회 및 주문 상태 변경 기능을 구현했습니다.

프로젝트 전체 과정에서 Spring Boot의 계층형 구조와 Spring Security의 인증·인가, JPA Entity 관계, 데이터베이스 연동을 직접 구현하며 백엔드 개발의 기본 구조를 이해하는 데 집중했습니다.

04

Application Architecture

Browser 사용자 요청
↓
Controller HTTP 요청 처리
↓
Service 비즈니스 로직
↓
Repository 데이터 접근
↓
JPA / Hibernate ORM
↓
MySQL 데이터 저장

Controller에서는 HTTP 요청과 응답을 처리하고, Service에서는 회원가입, 장바구니, 주문 생성 등 핵심 비즈니스 로직을 담당하도록 구성했습니다.

Repository는 Spring Data JPA를 이용하여 데이터베이스 접근을 담당하도록 분리했습니다.

Entity는 Member, Product, Cart, Order, OrderItem으로 구성했으며, JPA 연관관계를 활용하여 회원과 주문, 주문과 주문 상품, 상품과 장바구니 등의 데이터 관계를 표현했습니다.

06

Spring Security

Spring Security를 사용하여 로그인 인증과 사용자 권한 관리를 구현했습니다.

회원가입 시 PasswordEncoder를 사용하여 사용자의 비밀번호를 BCrypt 방식으로 암호화한 뒤 데이터베이스에 저장하도록 구성했습니다.

로그인 과정에서는 UserDetailsService를 구현한 CustomerDetailsService에서 username을 기반으로 회원을 조회하고 사용자의 권한을 Spring Security에 전달하도록 구현했습니다.

또한 관리자 URL인 /admin/**에 대해 ADMIN 권한을 가진 사용자만 접근할 수 있도록 권한을 제한했습니다. 

.requestMatchers("/admin/**")
.hasRole("ADMIN")
07

Troubleshooting

ISSUE 01

Controller에 로직이 집중되는 문제

Problem

프로젝트 초기에는 Controller에서 Repository를 직접 호출하여 데이터를 처리하는 방식으로 기능을 구현했습니다.

하지만 상품, 회원, 장바구니, 주문 등 기능이 늘어나면서 Controller에서 데이터 조회와 처리 로직이 함께 섞이기 시작했습니다.

Solution

Service 계층을 별도로 구성하여 비즈니스 로직을 Service로 이동했습니다.

이후 Controller는 요청을 받고 Service를 호출하는 역할에 집중하도록 구조를 분리했습니다.

Result

Controller → Service → Repository 구조를 적용하면서 각 계층의 책임을 명확하게 구분할 수 있었습니다.

ISSUE 02

Spring Security와 회원 데이터 연결

Problem

로그인 기능을 구현하면서 Spring Security가 인증 과정에서 데이터베이스의 회원 정보를 조회하고 권한까지 전달해야 했습니다.

Solution

UserDetailsService를 구현하고 MemberRepository를 사용하여 username을 기준으로 회원을 조회했습니다.

조회한 Member의 username, 암호화된 password, role을 이용하여 Spring Security의 UserDetails로 변환했습니다. 

Member member =
        memberRepository.findByUsername(username);

return new User(
        member.getUsername(),
        member.getPassword(),
        List.of(
            new SimpleGrantedAuthority(
                member.getRole()
            )
        )
);
ISSUE 03

장바구니에서 주문까지 데이터 흐름 구현

Problem

장바구니에 담긴 상품을 실제 주문 데이터로 변환하는 과정에서 회원, 상품, 수량, 가격 정보를 연결해야 했습니다.

Solution

현재 로그인한 회원의 장바구니를 조회한 뒤 각각의 Cart 데이터를 OrderItem으로 변환했습니다.

이후 주문 총 금액을 계산하고, 주문이 생성된 뒤 기존 장바구니 데이터를 삭제하도록 처리했습니다. 

for (Cart cart : cartList) {

    OrderItem orderItem = new OrderItem();

    orderItem.setOrder(order);
    orderItem.setProduct(cart.getProduct());
    orderItem.setCount(cart.getCount());
    orderItem.setPrice(
        cart.getProduct().getPrice()
    );

    orderItemRepository.save(orderItem);
}
ISSUE 04

동일 상품의 장바구니 수량 처리

Problem

이미 장바구니에 들어있는 상품을 다시 추가했을 때 동일한 상품이 여러 행으로 생성되지 않고 수량이 증가하도록 처리할 필요가 있었습니다.

Solution

Member와 Product를 함께 기준으로 기존 Cart 데이터를 조회한 뒤,

기존 데이터가 존재하면 count를 증가시키고, 존재하지 않는 경우에만 새로운 Cart를 생성하도록 구현했습니다.

What I Learned

LAYER Select Shop 프로젝트를 통해 Spring Boot 기반 웹 애플리케이션의 전체적인 개발 흐름을 직접 경험했습니다.
